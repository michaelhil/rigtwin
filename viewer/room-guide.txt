# Synergon

This guide is written for AI agents. It helps an agent carry out what its user asks for in Synergon, for example: open a named scene, place, move or swap a station, desk or display in the room, adjust a seat or monitor, seat an operator, measure a viewing distance or clearance, run an assessment, or start a new workspace, project or scene. People working by hand can ignore it and open the viewer at /workspaces.

Synergon is a work environment layout, design and evaluation tool. All paths below are on the same origin as this guide.

## The hierarchy: Workspace -> Project -> Scene
- A workspace holds projects. A project holds scenes, plus its record, named versions and saved assessments.
- A scene is what the viewer shows and what you edit: a room (walls, door, window), zero or more placed assets (stations, desks, displays) and optionally one seated operator, with its own revision and undo history. Inside a scene the viewer can show one asset on its own ("Show one asset"); that only changes the view.
- A scene opens at /workspaces/{sceneId}. The URL names only the scene; GET /api/scenes/{sceneId}/meta tells you its workspace and project.
- Names repeat (every project can have a "Scene 1"). Act by ID. If a name the user gives matches more than one item, list the matches with their workspace and project and ask which one.

## Find the scene the user means
1. If the user gave a link /workspaces/{id}, the id is the scene. Otherwise GET /api/workspaces lists workspaces ({id,name}); on the public sandbox it lists only the shared workspace, and the user's own workspaces open from their links.
2. GET /api/workspaces/{workspaceId} returns its projects and their scenes ({id,name}) in one answer.
3. GET /api/scenes/{id}/state gives the scene, its version, room, placements and optional person. GET /api/scenes/{id}/discover?query=display searches within the scene and the installed library. Scope another discovery call with instance=<instance ID> to inspect that placement's members and joints. Choose by instance ID and local member ID. The summary gives each placement in metres and degrees. A scoped match adds footprintRoom (four east/north corners in metres) and the asset frame. For a joint, value is its current absolute setting in metres or radians, axis is in its mount frame, and axisRoom points in the positive direction in east, north, up order. Revolute angles follow the right-hand rule. Ball joints take roll/pitch/yaw. Query a single discovered joint ID when you need its sign or range. Two copies of a station have different instance IDs and may have identical member IDs. Discovery and GET /api/scenes/{id}/meta report liveConnections, the number of open viewers of the scene. The browser owns its camera and selection.
4. GET /api/commands gives argument schemas and units. GET /api/catalog gives exact installed release pins with model/manifest URLs, anchors, members, joints and footprints. A display swap keeps the placement and tests compatibility. Install or choose the exact pin.

## Create a workspace, project or scene
POST /api/projects/command with Content-Type: application/json and X-Synergon: 1, body {"id":"<command>","args":{...}}. GET /api/projects/commands lists the schemas.
- {"id":"demo.open","args":{}} gives a demo scene (a furnished control room) of its own and returns {scene}; pass that scene again ({"scene":"<id>"}) to reset it to the default first. Use it when the user wants to try something without touching their own scenes. Demo scenes are never listed.
- {"id":"workspace.create","args":{"name":"Study"}} creates a workspace with a first project and an empty scene and returns {workspace, project, scene}. Add "template":"demo" for a furnished control room.
- {"id":"project.create","args":{"workspace":"<id>","name":"Phase 2"}} adds a project with a first scene; the answer's scene is its ID.
- {"id":"project.scene","args":{"project":"<id>","name":"Option B"}} adds a scene to a project.
- workspace.rename, project.rename and scene.rename change names. project.open {"scene":"<id>"} returns the project that holds a scene.
Omit a name to get the next default (My workspace, Workspace 2; My project, Project 2; Scene 1, Scene 2). Tell the user the link /workspaces/{scene} of anything you create.

## Edit or measure
POST /api/scenes/{id}/command. Send Content-Type: application/json and X-Synergon: 1. Use {"id":"instances.move","args":{"instance":"<resolved ID>","x":3.25},"expectedVersion":<scene version>}. A success returns ok, version, result, and recorded for an edit. Check ok on every reply. On overlapping stale changes, re-read state before deciding how to proceed. A failed edit leaves the scene intact. Undo a particular edit with {"id":"undo","args":{"version":<recorded version>}}.

A placement uses the asset's floor anchor, in metres east (x) and north (y) from the southwest corner. Positive yaw turns east towards north in degrees. Local joint settings are metres or radians. Use a discovered part’s controls to find its joints. pose.set changes one joint. pose.apply submits coupled axes on one instance as a single undoable edit. The room is Z-up. The door is on the south wall and the window is on the north wall. Opening offsets are measured from the west wall.

To add another copy of a placed asset, take its exact release pin from discover and call instances.add with a new instance ID, label, x, y and yaw. Use the installed release footprint (local min/max relative to its floor anchor) with existing placements to choose space. A scoped discover call after the edit returns its placed footprintRoom. Use instances.move to reposition it. Verify what fits and any required access clearance.

measure.distance takes from and to, each {"instance":"...","member":"..."}. Every placement has the floor member. person.measure uses the seated operator's eyes and a qualified target. person.set binds a person and local gaze/limb targets to a compatible host. measure.clearance reports the plan distance between the door threshold and a selected footprint and the longest unblocked span across the threshold. Both measurements return their endpoints and bounding edges. These are layout measures.

## Shared sessions and tools
GET /api/scenes/{id}/live streams snapshot events. The first event contains the current scene and revision, including after a reconnect. The UI, HTTP, CLI and scene MCP endpoint use the same scene writer.
For MCP, POST JSON-RPC to /api/scenes/{id}/mcp for one scene's tools, or /api/projects/mcp for the workspace, project and scene commands above. Initialize, then tools/list. tools/call uses underscore names (instances_move), with command arguments and optional expectedVersion. HTTP works directly without client setup.
In the repository, bun run rig workspaces --server <origin> searches this installation. bun run rig discover '{"query":"display"}' --scene <scene page URL> discovers objects. bun run rig list --server <origin> prints command schemas.

## Assess a layout
Open Assessment or call assessment.profiles through the scene command endpoint. Choose a source profile and record known facts with assessment.configure. Run assessment.run to see findings, their bindings, limits, sources and uncertainties. Unknown or unbounded inputs remain open. A stored run replays from its frozen inputs with assessment.replay. The source-checked criterion text and machine-readable rules are available at /standards/workstation-screening.md and /wiki/85-standards/workstation-screening.html.

## Local installation only
Open /projects for project folders, their scenes, named versions and transfers. The commands project.record, project.save, project.restore, project.compare, project.move, project.export and project.import use the same POST /api/projects/command envelope. The public sandbox refuses them. An embedded transfer carries exact releases to an offline installation. A linked transfer requires matching release pins at the receiving installation. Use project.help in the command-line client to see file import/export options. Store customer requirements in the private project on your installation.
