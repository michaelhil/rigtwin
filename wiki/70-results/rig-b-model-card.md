# Model card of the Rig B asset

## TL;DR

- **What it is:** a parametric, articulated layout model of a seated teleoperation station ("Rig B"), generated by code from 305 parameter records: 46 parts with geometry in five groups, 2 screen surfaces, 20 joints, 14 reference frames; 28,070 triangles, 67 draw primitives, 0.72 MB (build `0b6d8248b63f`). Since 2026-11-25 seven more reference frames, empty markers for the manikin, and 3 grip records (309 in all) make build `098d38cfc6c3`, with the same geometry byte for byte.
- **How it is known:** 3 records are the owner's figures, 22 come from makers' data, 80 from photo measurement, **179 are assumed and 21 invented**. No size has been checked against a tape. Depth along the main photos' line of sight cannot be checked from the photos at all.
- **Motion:** 13 adjustments and 7 runtime controls. 9 joints are seen, 5 inferred and **6 assumed** (all seat adjustments and the pedal tray); the viewer lets a person use the assumed ones, tagged "assumed range".
- **The owner's three figures all conflict with the photos** (platform 1.50 × 1.41 m, not 1.5 × 1.5; seat back top 1.28 m above the deck, not 1.4; 1.2 m fits headrest to screen, not eye to screen). The model follows the photos until a tape decides.
- **Not qualified for** any statement about which operators fit, posture scores, legibility or viewing-angle verdicts, clearance verdicts under about 13 cm (seat) or 10 cm (elsewhere), compliance, or the touchscreen arm's reachable range.

Terms (class, tier, basis, joint, reference frame) are explained in the
[glossary](../00-overview/glossary.md); the file formats in the [asset contract](../40-method/asset-contract.md).
Numbers on this page come from the final build of 2026-11-23 (`bun run build`, description file
`assets/rig-b/build/rig-b.manifest.json`) unless another source is named.

## What it is for, and what it is not

**Intended uses** (*judgment*, from the requirements [R-10](../10-request/requirements.md#r-10) to
[R-13](../10-request/requirements.md#r-13) and [R-55](../10-request/requirements.md#r-55)):

- Show the station's structure: which parts exist, what carries what, what moves with what.
- Serve as the shared, re-measurable geometry for later assessment and simulator work: every reference
  point, joint and screen surface has a stable name a program can find.
- Ask the right questions: every value says how it is known, so the model doubles as a list of what to
  measure ([measurement results](../50-implementation/measurement-results.md#the-most-useful-tape-measurements)).
- Show people the rig in a browser ([viewer](../50-implementation/viewer.md)).

**Not intended:** photorealism, fine detail (no screws, cables, stitching, logos or text, by decision
[D-16](../20-decisions/decision-log.md#d-16) and [D-27](../20-decisions/decision-log.md#d-27)), the room,
the van, or the machines the rig controls. The full "not qualified for" list is at the
[end of this page](#not-qualified-for).

**How the viewer shows them.** Assumed joints are usable ([D-31](../20-decisions/decision-log.md#d-31)):

**Why the seat references are "estimated".** A standardised seat index point (ISO 5353) needs the
seat's adjustments set to the middle of their ranges and a loaded measuring device, or the seat maker's
figure. None of that exists here, so the frames are labelled estimates
([D-11](../20-decisions/decision-log.md#d-11), [standards](../80-reference/standards.md)). Expected error:
about ±70 mm vertically and ±60 mm or more front to back. The live reference rests on the backrest
surface at cushion level, which no Rig B photo shows (−0.59 ± 0.04 m, borrowed from other rigs).

**The eye points** are built from the live seat reference with sitting eye heights of 0.685 / 0.765 /
0.845 m above the seat surface (class `assumed`, basis `standard_default`, quoted from memory of
published British adult tables, not looked up), an assumed cushion compression of 0.02 m and a
forward offset of 0.2 ± 0.04 m. They move with the seat base but **not** with the recline joint. Treat
them as placeholders ([I-14](../60-lessons/ideas.md#i-14)).

## Updating the model when tape measurements arrive

The mechanism is *tested* (on a scratch copy of the parameter folder, see
[filling gaps](../40-method/filling-gaps.md#overriding-with-a-real-measurement)); the before-and-after
report the plan asked for is **not automated**.

1. **Keep the old description file:** copy `assets/rig-b/build/rig-b.manifest.json` somewhere outside
   the build folder. It holds every estimate with its range.
2. **Write each tape value** into `assets/rig-b/params/measured.toml` (the file does not exist yet)
   under the same key as the estimate, as a complete record: `value`, `unit`, `range` (the tape's
   tolerance), `class = "measured"`, `basis = "user"`, `tier`, and `evidence` saying who measured,
   when, with what, and between which two points.
3. **Rebuild and check:** `bun run build`, then `bun run check`. No code changes. The file is read
   last, so its record replaces the estimate; the description file marks it
   `"source": "measured.toml"` and `"replaces": "<group file>"`; everything that depends on the key
   moves with it. The estimate stays in its group file as the method's track record.
4. **Score the estimate** for each measured key: *in band* if |tape − estimate| ≤ the estimate's
   range, *out of band* otherwise, *no claim* if the estimate had no range. The plan's rule for "sizes
   verified" is at least 8 of 10 taped values in band ([approved plan](../30-plan/approved-plan.md#5-success-criteria)).
   An agent can do it with this snippet (Python standard library; *tested* on a simulated pair of
   description files):

   ```python
   import json, sys
   old = json.load(open(sys.argv[1]))["parameters"]   # the copy from step 1
   new = json.load(open(sys.argv[2]))["parameters"]   # the rebuilt description file
   for k, r in new.items():
       if r.get("source") != "measured.toml" or k not in old: continue
       o = old[k]
       if not isinstance(r["value"], (int, float)): print(k, "list value: compare by hand"); continue
       d = r["value"] - o["value"]
       band = "no claim" if o.get("range") is None else ("in band" if abs(d) <= o["range"] + 1e-9 else "OUT OF BAND")
       print(f"{k}: estimate {o['value']:.4f} ± {o.get('range')} ({o['class']}), tape {r['value']:.4f}, {d:+.4f} m: {band}")
   ```

5. **Look** at the changed parts in the viewer's "How sure are we?" colouring and through the solved
   photo cameras; a value out of band means its siblings measured the same way may be off too.
6. **Record** the result: update this page's tables, the scores on the
   [measurement results](../50-implementation/measurement-results.md) page, and a dated entry in the
   [log](../log.md); then redeploy ([deployment](../50-implementation/deployment.md#updating-production-after-a-change)).

The ten measurements that would settle most are listed on the measurement results page; the questions
that go with them are on [next steps](../90-next/next-steps.md).

## Not qualified for

Whatever its visual quality, this model must not be used for:

1. **Any statement about which operators fit** the station (small or large, percentile coverage).
2. **Any posture score** (joint angles, comfort or load ratings of a posed manikin).
3. **Any legibility or viewing-angle verdict** on the monitor or touchscreen: the viewing distance is
   the least certain distance in the model (0.89 m modelled; the owner gave 1.2 m; the monitor is
   on an arm; its distance cannot be checked from the photos).
4. **Any clearance verdict with less than about 13 cm margin where the seat is involved, or about
   10 cm elsewhere.**
5. **Any compliance statement** against a standard. Several ranges were filled from typical values; a
   value filled from a standard cannot be assessed against that standard.
6. **The reachable range of the touchscreen arm**: its base is not visible in any photo and its ball
   ranges are assumed.

These limits come from the approved plan ([success criteria](../30-plan/approved-plan.md#5-success-criteria))
and hold until the critical dimensions are taped, the seat's adjustments confirmed and the reviewer's
detection threshold measured ([I-01](../60-lessons/ideas.md#i-01), [I-04](../60-lessons/ideas.md#i-04)).
How the result was judged: [goal assessment](goal-assessment.md); what is weak: [critique](critique.md).
